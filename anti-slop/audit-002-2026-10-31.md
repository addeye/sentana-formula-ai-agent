## 1. Implemented Fixes

### Finding 1 (HIGH): Input boundaries do not meet 3:1 non-text contrast (R-25, WCAG 1.4.11)
- **Shared CSS (`demo.css`):** Set resting border for `input, select, textarea` and framework classes `.form-control, .form-select` to `#64748b` (slate-500). Also updated `.demo-edit` border to `#64748b`.
- **Tailwind templates (`login.html`, `admin.html`):** Updated input, select, textarea, and action button borders to `border-slate-500`.
- **Contrast calculation:** `#64748b` has a relative luminance of ~0.174, yielding a contrast ratio of **4.76:1** against `#ffffff` and **4.55:1** against `#f8fafc`, well above the 3:1 requirement for non-text boundaries.

### Finding 2 (HIGH): Bootstrap login links do not receive the intended 44px hit area (R-03)
- **Shared CSS (`demo.css`):** Styled `.demo-link` with `display: inline-flex; align-items: center;` so that `min-height: 44px` is respected by the layout engine.
- **Markup (`bootstrap5/login.html`, `tailwind/login.html`):** Wrapped login preview links in vertical flex containers with `gap-2` to prevent collision and ensure full 44px hit targets across breakpoints.

### Finding 3 (HIGH): Error recovery and edit row focus restoration across rerenders (R-32, C-4)
- **Retry focus (`demo.js`):** Clicking `#retry` transitions back to normal mode, rerenders, and moves focus to `#demo-state`. Focus is no longer lost on a hidden control.
- **Invoking row restoration (`demo.js`):** Table rows render Edit buttons with `data-product-id="${product.id}"`. When opening the editor, `lastEditId` stores the product ID. Upon cancellation or save, `closeEditor()` queries `rows` for `[data-product-id="${targetId}"]` and returns focus to the invoking row button. Creation workflows without an invoking row fall back to `#create-product`.

### Finding 4 (HIGH): Desktop disclosure depends on JavaScript for reachability (R-32, C-4)
- **Initial markup:** Both `bootstrap5/admin.html` and `tailwind/admin.html` declare `<details id="navigation" open>`.
- **Desktop CSS:** `@media (min-width: 768px)` positions `#navigation` in-flow as a sticky sidebar and hides `<summary>`. If JavaScript is disabled or fails to load, desktop navigation remains reachable and operable.

### Finding 5 (LOW): Real accessible mobile drawer with backdrop matching standard (R-05, C-1)
- **Native modal dialog:** Both admin templates include `<dialog id="navigation-dialog" aria-label="Main navigation">` with a close button and `#open-navigation` Menu button in the topbar.
- **Drawer behavior (`demo.js`):** Below 768px, `#navigation` is moved into `#navigation-dialog` without duplicating `<nav>` markup. Clicking Menu invokes `showModal()`, enabling native top-layer rendering, native focus trapping, backdrop click dismissal, and Escape dismissal. Dismissal restores focus to `#open-navigation`.
- **Breakpoint synchronization:** At 768px and above, the dialog closes if open and `#navigation` is moved back into `.shell` as the desktop sidebar.
- **No-JS fallback:** Without JavaScript, the open in-flow disclosure remains usable on both mobile and desktop.
- **Documentation update:** Updated `templates/README.md` and `references/web.md` to reflect the native modal drawer standard with in-flow disclosure fallback.
